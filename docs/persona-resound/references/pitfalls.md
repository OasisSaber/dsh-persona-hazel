# 常见坑：每一条都是真金白银踩出来的

这些坑不是理论推演，是实际项目中反复踩、反复修复后的记录。**大部分坑的根源是同一个：模型默认习惯 > 提示词规则，或 embedding 的边界没被识别。**

## 提示词层的坑

- ❌ **提示词堆砌规则**：加"别老用封印""保持温度""别用括号"这类禁令，模型要么理解偏、要么干脆不听。→ 治本在素材层，提示词只放不可压缩的。
- ❌ **提示词点名口癖**：把带引号的台词例句放提示词（"你是不是又想听你满姐唱歌了？"）→ 模型每条都加。→ 例句下沉到 behaviors/phrases/voice_samples（条件注入 + 真人原话）。
- ❌ **人格标签当规则**："回避型亲近者"让亲密场景一律冷处理、泛闲聊被人设绑架。→ 标签是 tell，行为叙述才是 show。
- ❌ **"省略号是常态"**：提示词这么写 → 模型满屏省略号（真人聊天符号极少）。→ 写"例外" + 后处理兜底。

## 参数层的坑

- ❌ **temperature 调低治"重复"**：降到 0.7 反而括号爆炸（模型走 RP 默认模板）。0.85 括号反而少。
- ❌ **frequency_penalty 调高压括号**：0.5 没压住还引入整句重复。→ 回退。
- ❌ **用参数压症状**：回复段数多就用 `SPLIT_MAX_PARTS` 压 → 对话变怪。→ 治本在提示词/素材（"把反问揉进同一句"），参数是治标。

## 检索层的坑

- ❌ **阈值靠肉眼调**：0.65→0.55 是拿几个案例看出来的，出了新问题又得重猜。→ 建检索评测（标注集 + hit rate@K），调参变测量。
- ❌ **不知道 embedding 的边界**：问句 vs 陈述鸿沟、句式聚团、指代性消息、纯情绪消息——每个都会让检索误命中或漏命中。→ 见 `retrieval-architecture.md`。
- ❌ **样本 user 描述过泛**："发不绿色的内容"被撒娇语境误命中。→ user 描述精确限定触发语境（"发黄段子/擦边"）。
- ❌ **短 query 向量"糊"**：≤4 字消息 embedding 后与多个无关话题相似度都偏高，阈值全放行。→ 短 query 先在会话语境扩充成完整句再检索。
- ❌ **单字/别名子串误触发**：关键词"区"撞"小区/地区/区服"。→ pattern 正则精确命中。

## 模型默认习惯（提示词管不住，必须后处理）

- ❌ **括号泛滥**：样本里带（小声）（心虚），few-shot 学着用。→ 样本清洗 + `clean` 后处理（剥前缀/限 1 个/拆段再清）。
- ❌ **省略号刷屏**：→ 归一 + 整条限频 + 剥开头犹豫前缀。
- ❌ **第三人称自指**：模型叙述自己用"她"（"灰泽满……她……"）。→ 后处理：回复里没其他第三人称名字时"她/他"→ 名字。**注意保护**：出现"女同学/满妈"等名字时不动（"她"可能指别人）。
- ❌ **复读机**：模型对情境相关句执着复读（自己的话进短期记忆后再被引用）。→ 检测最长公共子串覆盖 ≥60% 强制重生成。

## 数据与记忆的坑

- ❌ **记忆污染（字符串 "null"）**：LLM 提取"没有"时输出字符串 "null" 而非 JSON null → 存进卡 → 注入"这个绿冻在null"。→ 提取端过滤 + 入库端类型校验 + 注入端兜底，三端堵。
- ❌ **记忆提取 JSON 不规范**：裸键（`new_user_fact:` 缺引号）→ json.loads 崩 → 该轮记忆丢弃。→ 修复函数（补引号/尾逗号/围栏）+ 失败严格格式重试。
- ❌ **承诺/印象只增不减**：confidence 只升不降（封顶 1.0）、承诺无过期概念。跑几个月后过期记忆会慢慢污染。→ 需要记忆时间维度（衰减 + 过期），但短期看不出问题，可延后。
- ❌ **运行时数据进 git**：测试对话会污染记忆文件并制造提交噪声。→ 记忆文件 gitignore + 提供示例。

## 转化的坑

- ❌ **直播素材直接当聊天用**：不转格式，弹幕被当成 user、长独白整段保留。→ 必须"转聊天"：分离转述/回答、切分压缩。
- ❌ **手工编措辞**："被作业封印了"不是她原话，模型用了露馅。→ 措辞必须从素材提取。
- ❌ **一次性跑完流水线不给中间产物**：错译/乱码一路传染。→ 每步产物先展示审批。
- ❌ **作品"念过开头"≠ 原文在数据里**：被要求"念一下"时模型只能编。→ 要能逐字引用，必须把原文真入库。
