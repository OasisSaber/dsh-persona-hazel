# 蒸馏管线：从素材到人格数据

核心目标：把原始素材（音频/文字）变成模型能"直接引用、照着学腔调"的人格数据。**关键是中间要经过"转聊天"这一道工序**——原始素材的格式不等于聊天格式。

## 标准流水线

```
1. 收集素材        音频/录播/文字稿/聊天记录
2. 转写 + 清洗      音频 → 转写 → 繁体转简体/修错字/合并碎片
3. 节奏地图         判噪声，只标高质量话轮（聚焦场景）
4. 转聊天           分离"读弹幕 vs 回答"、切分压缩成 15-50 字短回复
5. 挖措辞指纹       从素材批量挖"同一意思 → 真实原话"
6. 生成场景化陈述   供背景记忆 RAG（50-120 字，锚定真实事件）
7. 人工审批         每步产物先展示，验证通过再往前
8. 向量化           陈述 → corpus 向量（`generate-vectors -i <产物>`）；其余人格数据 → 向量缓存（`precompute --all`，运行时读取）
```

## 先筛选后分析（最重要的一步）

- **判噪声**：寒暄（"哈哈哈""晚安"）、礼物感谢、转述粉丝话、读二创内容、重复 —— 全过滤，只提炼高质量话轮。
- **先判场次价值**：素材质量决定样本上限，花 5 分钟判定一场值不值得全流程处理，比闷头跑完强。
- **聚焦场景**：标注时只精标关心的场景（被夸/被质疑/失约…），其余归"其他"，避免分析被稀释。

## 转聊天（直播 ≠ 聊天）

这是最容易踩坑的一步。直播是"独白 + 读弹幕"，聊天是"一来一往"。

- **分离转述与回答**：转述的粉丝话是 user，她的回答才是 reply。单人声音素材尤其要区分——"粉丝问：XX" 是 user，她答的是 reply。
- **切分压缩**：一个独立意思 = 一条 15-50 字短回复，不能整段保留长独白。她说话是一个意思一个意思蹦的，不是一段话一口气说完。
- **给 user 写精确触发语境**：user 描述要限定真实触发情境，不要写泛泛的（"发不绿色的内容"这种过泛描述会导致误命中，应写"发黄段子/擦边"）。

## 挖措辞指纹

- **从素材提取，不手工编造**。手工编的措辞（"被作业封印了"）不是她原话，模型用了会露馅。
- 措辞要锚定**高频稳定**的说法（被夸 → "也没有啦"），日常即兴交给声音样本。

## 生成场景化陈述（供 RAG）

- **具体锚定真实事件**：让模型能"直接引用"，不给它"由头自己编"的空间（"客厅能说话"就是反面教材——太泛，模型会编细节）。
- 写"她在什么情境、做了什么、说了什么原话"，不是抽象概括。

## 审批与向量化

- **每步产物先人工审批**，验证通过再往前。不要一次性跑完全流程——错译、乱码会一路传染。
- **向量化前先校验 JSON 合法性**，再重新生成向量缓存。
- 改过人格数据文件后，**必须重跑对应的向量预计算**，运行时读的是缓存不是源文件。
