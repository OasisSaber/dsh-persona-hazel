# 检索与生成架构：多路注入 + 嵌入的边界

## 多路检索 + 融合

把"人格数据"变成"按当前消息情境**只注入相关部分**"的运行架构：

```
用户消息
  → 1 次 embedding（query 向量多路共用）
  → 各路检索：背景记忆 / 风格样本 / 行为 / 措辞 / 偏好 / 核心记忆
  → RRF 加权融合（行为 1.5 > 措辞 1.2 > 背景/样本 1.0）
  → 条数截断 + 字符预算截断
  → 按注入优先级组装进提示词
```

- **全程只调 1 次 embedding**：query 向量算一次，多路共用。
- **阈值 + 预算双控**：每路有相似度阈值（低于不注入）；融合后按字符预算截断（防止把全部上下文塞满）。
- **注入优先级 = 组装顺序**：人设 → 行为指令 → 背景记忆 → 长期记忆 → 会话记忆 → 措辞 → 风格样本 → 用户消息，每层决定一件事。

## 嵌入的边界（教科书没有，踩坑才有）

embedding 模型有一些**根本性局限**，纯 cosine 匹配解决不了。正确做法是识别这些边界，用别的机制补。

### 1. 问句 vs 陈述鸿沟

- 现象：用户问句（"你和女同学一起上学的事"）与叙述式记忆（"灰泽满提到…和女同学一起上学"）的相似度只有 ~0.51，而无关内容（"灰泽满是不是很懒"）反而 0.62。
- 后果：任何单一阈值都两难——设高漏掉真相关，设低注入不相关。
- 解法：**区分性词重叠门**。query 与记忆文本有实质词（去停用字后的 bigram）重叠才放行。这样阈值敢降，名词撞车但不相关的会被门挡住。

### 2. 句式聚团（embedding 不认意图）

- 现象："灰泽满你唱歌好听"（夸）和"灰泽满你怎么又迟到"（质问）同为"灰泽满你…"问句，在向量空间挤成一团，余弦把夸奖匹配成"被质疑"。
- 后果：靠 embedding 猜意图（夸/骂/请求）不可靠。
- 解法：**意图判断交给 LLM**。行为/意图归属用一次便宜 LLM 调用判定（结合最近对话），判别性词汇（敷衍/骗/鸽/迟到/黄桃/擦边）作确定性兜底。

### 3. 指代性消息

- 现象："能读给我听听吗"（指前面说的小说）不带任何话题词，检索不到记忆。
- 后果：模型手里没记忆，只能编造内容。
- 解法：**检索 query 结合会话话题补全**。消息是"必须结合前文才能懂"的指代性消息时，用补全句（带话题）做检索。

### 4. 纯情绪消息

- 现象："可惜🤭"被表情规则补全成"用户发了个偷笑的表情"，这条纯情绪句做检索会误命中无关样本（"偷笑"→ 命中"贺图/新衣服"样本）。
- 后果：模型拿到无关样本内容，跳题。
- 解法：**纯情绪消息跳过语义检索**（和纯表情消息一致），补全句只作语气提示注入，不用于检索。

### 5. 记忆的注入边界

- 记忆要**防复读**：自己说过的话只是历史背景，用户没追问就不重复。
- 记忆要**防污染**：LLM 提取的字段可能输出字符串 "null"（而非 JSON null），入库前要过滤；注入前也要兜底过滤历史遗留的 "null"。
- 记忆提取 JSON 可能不规范（裸键/尾逗号）→ 提取端修复 + 失败重试。

## 输出清洗（确定性兜底）

模型有默认习惯（RP 腔），提示词规则压不住的部分用**输出后处理**兜底：

- 括号：剥开头前缀、整条至多 1 个、拆段后再清。
- 省略号：归一、整条限频、剥开头犹豫前缀。
- 第三人称自指（"她"指自己）：对话里用名字自称，回复里没出现其他第三人称名字时，"她/他"→ 名字。
- 结巴（"那、那"）消融。
- 复读检测：与最近自己说过的话最长公共子串覆盖 ≥60% 就强制重生成。
